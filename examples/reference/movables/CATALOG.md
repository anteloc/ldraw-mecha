# Movable-element catalog

Twenty mock scenarios of classic (non-Technic) movable LEGO elements, three animation clips each, in one file: [`movables.blend`](movables.blend). Generated by `scripts/build_movables.py catalog` from `scripts/movable_clips.py`. See [`REPORT.md`](REPORT.md) for how the scenarios were built and checked.

## How to find a how-to

1. Pick a scenario by element (table below), or a movement style from the style index.
2. In `movables.blend`, open the scene of the same name (scene list: `S07 Treasure chest` …) to see that case alone, or the `Catalog` scene to see all twenty. Each scene's timeline markers name its clips.
3. Reuse the clip's Action (Blender) or its JSON keys (`clips/<scenario>.<clip>.json`); see *Reusing a clip*.

Timeline (24 fps): clip A plays in frames 1–144, B in 161–304, C in 321–464; between windows each element holds its rest pose. Every clip starts and ends at rest (all controls 0; spins end on whole turns).

## Easing used by the clips

Each key's interpolation applies to the segment that starts at it (Blender semantics). The Python evaluator `movable_clips.value_at` uses Blender's own easing equations, so the JSON values equal what Blender plays.

| Key name | Blender interpolation / easing | Typical use |
| --- | --- | --- |
| `SINE_IN_OUT` | SINE / EASE_IN_OUT | smooth start and stop (default) |
| `QUAD_IN` / `QUAD_OUT` | QUAD / EASE_IN, EASE_OUT | gravity fall; fast start, soft stop |
| `CUBIC_IN_OUT` | CUBIC / EASE_IN_OUT | slow, motorised moves |
| `LINEAR` | LINEAR | winches, motors, constant spins |
| `CONSTANT` | CONSTANT | holds (the value stays until the next key) |
| `BOUNCE_OUT` | BOUNCE / EASE_OUT | hitting a stop: falls, rebounds twice, settles |
| `BACK_OUT` | BACK / EASE_OUT (back = 1.70158) | overshoot about 10 % past the target, settle back |

## Reusing a clip

- **Data only:** `clips/<id>.json` holds the sparse keys (frame, value, Blender interpolation and easing), the value baked at every frame, and each channel's unit, range and meaning.
- **Blender:** every clip is an Action with one slot (`movable_controller`) keyed on the controller's custom properties (`["door"]`, `["lift"]` …). It plays on any controller with the same property names and meanings:

```python
import bpy
src = '/abs/path/output/movables/movables.blend'
with bpy.data.libraries.load(src, link=False) as (data_from, data_to):
    data_to.actions = ['S10_car_doors.both_doors']
action = data_to.actions[0]
ctrl = bpy.data.objects['CTRL_movable_06_double_cabinet']  # any controller with door_l / door_r
ad = ctrl.animation_data_create()
track = ad.nla_tracks.new()
strip = track.strips.new(action.name, 1, action)
strip.action_slot = action.slots[0]
```

- **Whole scenario:** append the collection `Sxx_key Title` (it holds the model, its rig collection, the controller with its NLA tracks and the SLOT_ empty); the Actions come along through the NLA strips.
- **On a new model:** rig the element with the same joint (axis and origin from the same connector pair, see the table and `Sxx_*/plan.json`), give the control the same name, unit and sign, and the clip values apply unchanged. Remeasure the target; check ranges against its own surroundings.
