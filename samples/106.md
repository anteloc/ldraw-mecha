# 106 UNICEF car: opening doors, roof and turning wheels

A small blue LEGO promotional car with UNICEF side panels, rigged so its two doors and roof open and its four wheels and spare wheel turn. It was the first, simplest test model while Codex built this project's animation toolkit, so the result is a rig you move by hand, not a recorded animation.

## How to view it

1. Open [106/rigged.blend](106/rigged.blend) in Blender 5.2 or later.
2. Select `CTRL_car106` and open **Object Properties → Custom Properties**.
3. Drag the sliders: `door_left`, `door_right` and `roof` open the doors and roof (up to 75°); `wheel_1` to `wheel_4` and `spare` turn the wheels.

## What was asked

The user asked for a reusable Python toolkit that lets agents analyse an LDraw model, find its mechanisms and rig them in Blender realistically, validated on progressively harder models.

>
> ## Goal
>
> We want to create a python toolset that can be used by agents to enable LEGO mechanisms to move and be controlled in a realistic way inside Blender, via rigs and animations.
>
> ## Context
>
> LEGO models can be encoded as LDraw source files, usually in `.mpd` or `.ldr` format.
>
> We are aiming at creating a toolset that will allow agents to:
>
> 1. Analyze an `.mpd` or `.ldr` LDraw model file
> 2. Determine mechanisms present in the model, like e.g. hinges, doors, windows, joints, axles, pistons, shafts, motors...
> 3. Plan for Blender animations, rigging, constraints, drivers, shape keys, motion paths, etc.
> 4. Once that is done:
>     - Convert the LDraw model file to `.glb` format
>     - Import into Blender
>     - Apply the planned animations, rigging, constraints, drivers, etc. to the imported `.glb` model
>

>     - ... that would then propagate the interaction through the required parts

>     - let's say like e.g. an engine with a transmission, pistons, etc

## What happened

1. The agent studied the existing hand-made rig of the 42000 racer in Blender and wrote an implementation plan.
2. It picked this car as the first, simplest test model. About 10 minutes into the session, the doors, roof, four wheels and spare wheel each had a working control.
3. It went on to the 928 spaceship hatch and the 42000 racer, then stopped mid-way. The session sat idle for almost three hours until the user said "continue".
4. A collision scan found the doors and roof hitting other parts at 90°. The scan also counted parts that merely touch as collisions, so the agent fixed it. It then set the door and roof limit to 75°, which passes.
5. Final checks passed: the saved file reopens, the rig can be rebuilt and removed cleanly, and two copies can live in one scene. The agent delivered at 03:52, together with the other two test models.

## Known limits

- There is no recorded animation: the file is a rig whose controls you move by hand.
- Doors and roof stop at 75°, because they hit other parts at 90°. The collision scan checked sample angles only.
- The steering wheel does not steer: this simple car has no steering mechanism.
- Motion is ideal and rigid: no friction or play.
